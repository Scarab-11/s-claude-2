# Jw_cad 建具平面データ（JW_OPT1B.DAT）

Jw_cad の **[作図] → [建具平面]** で使う建具データを、包絡処理が正しく効くように作り替えたものです。

## ファイル

| ファイル | 内容 |
|---|---|
| `JW_OPT1B.DAT` | **配布版（16件）**。これを Jw_cad のフォルダに入れる |
| `JW_OPT1B_扉厚折戸入り.DAT` | 扉厚を描く詳細版の折戸を含む16件版。復元用 |
| `JW_OPT1B_元データ.DAT` | 作り替える前の元データ。比較用 |
| `tools/check.py` | DAT を検査して建具一覧と属性を表示する |
| `tools/build.py` | 扉厚折戸入りから配布版を組み立てる |

`JW_OPT1B.DAT` を Jw_cad の実行ファイルと同じフォルダ（例 `C:\jww\`）に置きます。
既存のファイルを上書きするので、元のファイルは退避しておいてください。

編集したら Jw_cad に入れる前に必ず検査を通します。

```sh
python3 tools/check.py JW_OPT1B.DAT
```

## 元データからの変更点

| 内容 | 対象 |
|---|---|
| 建具端部の線を**選択色・選択レイヤ**に | 全建具 |
| 建具部分を**線色番号2**に | 全建具 |
| 木柱部分を**線色番号4**に | 7〜10番 |
| 折戸の点線部を**実線**に | 13・14番 |
| 折戸に**端部線を追加**（他の建具と同じ形状） | 13・14番 |
| 折戸の**軸を壁の中心に**（Y+35） | 13・14番 |
| 折戸の羽根のレイヤ欄を **`-1` → `-11`** | 13・14番 |
| 扉厚を描く詳細版の折戸を削除 | 元の15・16番 |
| 親子ドアーの**子扉400・450**を追加 | 15・16番 |
| 建具（扉・障子・羽根）を**線色番号6**に | 5・11〜16番 |
| **中心線を追加**（線色6・実線） | 1・11番 |
| 中心線を置くため**分割数を2から3に** | 1・11番 |
| 障子を**簡略形**にし、見込線を削除 | 5番 |
| 扉の**円弧を線色2**にし、扉の線だけ線色6を重ねる | 11・12・15・16番 |

建具名と終端パラメータは変更していません。
座標を動かしたのは折戸の Y+35 と5番の作り替えだけで、分割数を変えたのは1・11番だけです。
追加した親子ドアーも、12番の行をそのまま写して `300` を置き換えただけです。

**線色6にしたのは動く部分（扉・障子・羽根）と中心線だけ**です。
開口を示す建具線・躯体線・木柱・壁線は線色2（木柱は4）のままにしてあります。

## データの書式

標準の資料が手元に無いため、元データの解析と Jw_cad 上での実挙動から確かめた内容です。
確証のあるものだけを書いています。

### ファイル全体

```
#1/100平面用          1行目 = データセットの見出し
#
16                    登録件数（実際の建具の数と一致していないと表示が崩れる）
999
#
<分割数>  <建具名>     空白2個以上で区切る
<データ行>...
999                   終端
#
<分割数>  <建具名>     以下、建具の数だけ繰り返す
...
```

**文字コードは CP932（Shift_JIS）、改行は CRLF。** UTF-8 で保存すると建具名が化けます。
ファイル末尾には EOF マーカー `0x1A` が付きます。

### データ行

```
始点番号 終点番号 X1 Y1 X2 Y2 [線色 線種 レイヤ] [e 角度 コード]
```

- **始点番号・終点番号** … 分割数 n のとき、建具幅 W を (n−1) 等分した n 個の基準位置を指す。
  分割数5なら 1・2・3・4・5 が左から順の基準位置
- **X1 Y1 / X2 Y2** … その基準位置からのオフセット（mm）
- **線色** … `0` = 書込線色（＝そのときの選択色）、`1`〜 = 線色番号
- **線種** … `0` = 書込線種、`1` = 実線、`2` = 点線
- **レイヤ** … 下表
- **e 角度 コード** … その線を始点まわりに回転させる。コード `12`・`13` は円弧も描く（ドアーの
  開き軌跡）、`16`・`18` は線のみ

### レイヤ欄

| 値 | 意味 |
|---|---|
| `11` | レイヤグループ1・レイヤ1（固定） |
| `1A` | レイヤグループ1・レイヤA（固定） |
| `B` | 書込レイヤグループのレイヤB（固定） |
| `-11` | 選択レイヤ（書込レイヤ）に描く |
| `-1` | 建具属性を付けて書込レイヤに描く |

`-1` と `-11` の違いが今回の不具合の原因でした。次の節を参照。

### 見込の基準

通常の建具は **Y=0 が見込の基準面**で、見込 0〜70、建具線が Y=35、
端部線は −10〜80（壁の外へ上下10ずつはみ出す）。
はみ出した分は包絡処理で壁厚ぴったりに切り揃えられます。

元データの折戸だけは **Y=0 が折戸の軸そのもの**（±50）という別の基準で描かれていたため、
壁の中心からずれていました。全体を Y+35 して他の建具と揃えてあります。

## 包絡処理の不具合について

### 症状

折戸だけ、**建具用包絡（Shift を押しながらの終点指示＝中間線消去）**をすると端部が崩れました。
普通の建具（ドアー・引違いなど）は正常でした。

### 原因

建具用包絡は**建具属性の付いた線を処理対象**にします。
折戸の羽根はレイヤ欄が `-1`（建具属性あり）だったため包絡の対象になり、
羽根が端部線から**斜めに枝分かれ**することで余計な交点ができて、端部の処理が壊れていました。

羽根のレイヤ欄を **`-11`（建具属性なし）** にすると羽根が包絡の対象から外れ、
端部線と壁だけで包絡が成立して正常になります。

### 切り分けの記録

同じ骨格に要素を1つずつ足して、壁に配置 → 建具用包絡 で確認しました。

| 試したこと | 結果 |
|---|---|
| 端部線の線色・線種・レイヤを変える（`0 0 -11` / `0 1 -11` / `0 0 -1` / `0 1 -1`） | 変化なし。属性取得で正常な建具と同一と確認済み |
| 端部線の長さを変える（±50 / ±65 / −10〜80） | 変化なし |
| 終端コードを変える（999 / 995 / 991） | 変化なし |
| 行の並び順を変える | 変化なし |
| 分割数を変える（2 / 3 / 5 / 9）※端部線＋建具線のみの骨格 | **すべて正常**。骨格自体は問題なし |
| 骨格＋中央の縦線 | 正常。中央線はシロ |
| 骨格＋羽根60度 | **崩れる** |
| 骨格＋羽根90度 | 正常。端部線と重なる向きなら問題ない |
| 羽根を内側へ2mm / 10mm ずらす | 崩れる |
| 羽根の起点を端部線の外（Y=81）へ | 崩れる |
| 羽根を80度に | 崩れる |
| 羽根の建具部分を手作業で曲線属性にする | **正常**（曲線属性は包絡の対象外になるため） |
| **羽根のレイヤ欄を `-1` → `-11` に** | **正常** ← 採用 |
| 羽根のレイヤ欄を `0` / `1` / 属性欄なしに | 線色やレイヤが崩れる。`属性欄なし` は壁と同属性になり包絡に飲み込まれて羽根が消える |

曲線属性でも直りますが、建具データの書式に曲線属性を指定する項目は見つかりませんでした。
`-11` なら DAT だけで完結し、配置のたびに手作業をする必要がありません。

## 扉の線と円弧を別の線色にする方法

扉の線と開き軌跡の円弧は、`e 角度 12`（または `13`）という**1行から両方が描かれる**ため、
線色欄は1つしかありません。そのままでは別々の線色にできません。

そこで**線色2で「線＋円弧」を描き、その上に線色6で「線だけ」を重ねて**います。

```
1 3 0  35  0  35    2 0 -11  e  90  12   ← 扉の線と円弧を線色2で
1 3 0  35  0  35    6 0 -11  e  90  16   ← 扉の線だけを線色6で重ねる
```

`16` は線のみを描くコードで、折戸の羽根でも使われています。
重ねる行は座標・角度・レイヤ欄を元の行と揃えてあるので、包絡の扱いも同じになり、
2本がずれることはありません。

**扉の線は2本重なっています。** 図面上は線色6が上に見えますが、下に線色2の線が残るため、
[データ整理] の重複整理をかけるとどちらかが消えて色が変わる可能性があります。

## 中心線について

1・11番には建具の中央を示す縦線が入れてあります。

```
2 2 0 -50 0 120     6 1 -11
```

- **長さは見込（0〜70）の上下に50ずつ**で Y −50〜120。壁から50mmずつはみ出します
- **建具属性を付けていません（レイヤ欄 `-11`）**。付けると建具用包絡で壁厚ぴったりに
  切り詰められ、はみ出しが消えてしまいます
- 線色6・実線の固定です

**中心線を置くには分割数を増やす必要があります。** 座標は分割点からのオフセットでしか
指定できず、分割数2では基準点が両端の2つしかないため中央を指せません。分割数3にすると
真ん中の基準点ができるので、そこに縦線を置いています。既存の行は `1 2`→`1 3`、
`2 2`→`3 3` と読み替えただけで、描かれる形は変わりません。

折戸（13・14番）は元から中央に縦線を持っているのでそれを流用しました。
こちらは長さ（Y −15〜85）も建具属性（`-1`）も元のままで、線色だけ6にしています。

## 親子ドアーの子扉寸法について

子扉の寸法は**座標に直接書かれた固定値**です。12番なら次の4か所の `300` がそれにあたります。

```
2                            親子ドアー（子扉300）
s    100  100
1 1   0   0   0 100   0 0 -11              ← 左端部線
1 2   0  50   0  50   2 0 -1               ← 建具線（P1→P2）
2 2 300   0 300 100   0 0 -11              ← 右端部線（P2 から右へ 300）
1 2   0  50   0  50   2 0 -1  e   90  12   ← 親扉（P1→P2）
2 2 300  50   0  50   2 0 -1  e  -90  13   ← 子扉（P2+300 → P2）
991  100  100
```

この書式で**指示した幅に追従できるのは分割点で表した寸法だけ**で、mm で直接書いた寸法は必ず固定です。
分割数 n は指示幅を (n−1) 等分するため、比率でしか表せません（13番の折戸が分割5＝4等分、
14番が分割9＝8等分でこれを使っています）。

実際の親子ドアは子扉が定尺なので、比率にすると実物と合いません。
そのため**寸法違いを別の建具として登録**する方式にし、子扉400・450 を15・16番に足しました。
別の寸法が要るときは `tools/build.py` の `WIDTHS` に足します。

`s`/`S` の行と終端の `995`・`991` に寸法入力の仕組みがありそうですが、
各コードの意味は確認できていません（下記「確認できていないこと」参照）。

### 12番・15番・16番の見込は100

親子ドアーだけ見込が 0〜100・建具線が Y=50 で、他の13件（0〜70・Y=35）と基準が違います。
端部線のはみ出し（他の建具の上下10mm）もありません。見込100の壁で使う前提のデータです。

## 扉厚を描く詳細版の折戸を外した理由

13・14番には無い `e 10 18` という行が元の15・16番には各4行あり、
これは**回転の中心が分割点そのもの**だと考えられます。

元データは折戸の軸が Y=0、つまり分割点と一致していたので成立していましたが、
軸を壁の中心に合わせるため全体を Y+35 したことで、回転の起点（Y=35）と
回転の中心（Y=0）が35mmずれました。この2件は扉厚を表すために回転を数珠つなぎに
しているため、そのずれが増幅して形が破綻します。

軸を戻せば形は直りますが、今度は壁の中心からずれて包絡も効かなくなり元に戻ってしまいます。
**「軸を壁中心に合わせる」と「扉厚を表現する」が両立しない構造**です。

1/100 の図面に扉厚は不要なため、配布版からは外しました。
必要になったら `JW_OPT1B_扉厚折戸入り.DAT` から戻せます。

## 確認できていないこと

次の項目は元データからの推測で、裏が取れていません。本番データでは触っていません。

| 項目 | わかっていること |
|---|---|
| `S` / `s` の行 | 9・10番（建具名が「◯mm基準」）と12番にある。7・8番（建具名が「固定」）には無い |
| 終端の `999` / `995` / `991` | 「固定」の建具が `999`、「基準」の建具が `995`、親子ドアーが `991` |
| 終端の後ろの2つの数値 | 7・8番が `100 50`、9番が `100 100`、10番が `100 50`、12番が `100 100` |

書式を解説しているサイト（アジアポケット、Jwcad操作マニュアル、PERSC JOURNAL など）は
この作業環境のプロキシに遮断されていて本文が読めませんでした。
このリポジトリの記述は、すべて元データの解析と Jw_cad 上での実挙動から確かめたものです。

## 建具データファイルの種類

| ファイル | コマンド |
|---|---|
| `JW_OPT1*.DAT` | 建具平面 |
| `JW_OPT2*.DAT` | 建具断面 |
| `JW_OPT3*.DAT` | 建具立面 |
