# Jw_cad 建具平面データ

Jw_cad の **[作図] → [建具平面]** で使う建具データを、包絡処理が正しく効くように作り替えたものです。
`JW_OPT1B.DAT`（15件）と `JW_OPT1.DAT`（22件）の2セットがあり、同じ仕様を当ててあります。

## ファイル

| ファイル | 内容 |
|---|---|
| `JW_OPT1B.DAT` | **配布版（15件）**。これを Jw_cad のフォルダに入れる |
| `JW_OPT1B_扉厚折戸入り.DAT` | 配布版から外した3件を含む16件版。復元用 |
| `JW_OPT1B_元データ.DAT` | 作り替える前の元データ。比較用 |
| `JW_OPT1.DAT` | **配布版（22件）**。もう1つのデータセット |
| `JW_OPT1_元データ.DAT` | その元データ（24件）。**末尾に Jw_cad 公式の書式説明**が入っている |
| `tools/check.py` | DAT を検査して建具一覧と属性を表示する |
| `tools/build.py` | JW_OPT1B.DAT を組み立てる |
| `tools/build_opt1.py` | JW_OPT1.DAT を組み立てる |

`JW_OPT1B.DAT` を Jw_cad の実行ファイルと同じフォルダ（例 `C:\jww\`）に置きます。
既存のファイルを上書きするので、元のファイルは退避しておいてください。

編集したら Jw_cad に入れる前に必ず検査を通します。

```sh
python3 tools/check.py JW_OPT1B.DAT
```

## JW_OPT1.DAT について

元データ（24件）に `JW_OPT1B.DAT` と同じ仕様を当てたものです。組み立ては
`python3 tools/build_opt1.py`。当てた規則は次のとおりです。

| 部位 | 指定 |
|---|---|
| 端部線（両端ブロックの X=0 の縦線） | `0 0 -11`（選択色・選択レイヤ） |
| 枠・躯体・見込線・開口を示す建具線 | 線色2 |
| 扉・障子・戸・召し合わせなど動く部分 | 線色6 |
| 扉の円弧 | 線色2（コード `10` ＝円弧のみ） |
| 扉の線 | 線色6（コード `16` ＝線のみ） |
| 中心線 | Y −50〜120・線色6・実線・**建具属性あり**（`6 1 -1`） |

- **扉厚を描く折戸2件（元データの [13][14]）は削除**しました。22件になり、
  以降の建具名は `[1]`〜`[22]` に振り直してあります（元の [15] が [13] になる）。
- 中心線は元データの 1・3・4・6〜12・15〜23番に入れています。[2][5] は分割4で
  中央に基準点が無いため入れられません。[24] は対象外です。
- **中央にすでに縦線がある建具は、その線を Y −50〜120 に伸ばして中心線と兼用**しています。
  別に足すと線が二重になるためです。
- 中心線を置くため、分割2だった建具は分割3にしました。既存行のブロック番号を
  読み替えただけで、描かれる形は変わりません。
- **中心線は全件 建具属性あり（`-1`）**にしてあります。`-11` にすると、見込線などで
  閉じた領域ができている建具で、壁の中を通る部分が中間線消去で切られて上下に分断されます。
  `JW_OPT1B.DAT` の1・11番は見込線を持たないため `-11` のままです。
- **元データに端部線が無い建具**（[1][2][7][9][10][11][12][15]）には選択色の線がありません。
  形を増やすことになるので追加はしていません。
- **[5][6] は両端の枠（線色2）を削り、代わりに開口いっぱいの見込線を足しました。**
  端部線（選択色）と合わせて開口が矩形になります。
  同じ枠の作りをしている [3][4] は指示が無かったのでそのままです。
- **[24] は元から線色が指定済み**で用途も不明なため、手を触れていません。

## データの書式

**出典は `JW_OPT1_元データ.DAT` の末尾に収録されている「ＪＷ＿ＣＡＤ　パラメトリック建具
データ説明」**です。以下はその要約に、実機で確かめた挙動を補ったものです。

建具（図形）の数は**1ファイルにつき16まで**とされています。

### ファイル全体

```
#1/100平面用          1行目 = データセットの見出し
#
15                    登録件数（実際の建具の数と一致していないと表示が崩れる）
999
#
<分割数>  <建具名>     空白2個以上で区切る
<データ行>...
999                   終端
#
<分割数>  <建具名>     以下、建具の数だけ繰り返す
...
```

**文字コードは CP932（Shift_JIS）、改行は CRLF。** UTF-8 で保存すると建具名が化けます。
ファイル末尾には EOF マーカー `0x1A` が付きます。

### データ行

```
始点番号 終点番号 X1 Y1 X2 Y2 [線色 線種 レイヤ] [e 角度 コード]
```

- **始点番号・終点番号** … 分割数 n のとき、建具幅 W を (n−1) 等分した n 個の基準位置を指す。
  分割数5なら 1・2・3・4・5 が左から順の基準位置
- **X1 Y1 / X2 Y2** … その基準位置からのオフセット（mm）
- **線色** … `1`〜`6`。`0` または省略で書込線色（＝そのときの選択色）
- **線種** … `1`〜`9`。`0` または省略で書込線種。**百の位に線幅を 1/100mm 単位で書ける**
  （`2001` なら線種1・線幅0.2mm）
- **レイヤ** … `0`〜`F`。下表
- **e 角度 コード** … 円弧の指定。下記「円弧の指定」参照
- 線色 `10000` は文字、`30000` は点の指定になる（線種欄が文字種類／実点種類）
- **始点番号を `0` にすると、それ以降のデータは一覧表と作図時の仮線に表示されない**

部材数に制限はありませんが、**一覧表示と作図時の仮線表示は60本まで**です。

### レイヤ欄

レイヤグループは常に書込レイヤグループです。

| 桁数 | 意味 |
|---|---|
| 1桁（`B` など） | そのレイヤに描く。建具としての性質はそのまま |
| **2桁**（`1A`・`-11` など） | **下1桁が有効**。加えて**包絡処理における建具としての性質が解除される** |
| **3桁**（`-111` など） | 2桁と同じことに加え、**建具属性が解除**され、複写等の範囲指定で「建具」選択ができなくなる（壁等の線データ用） |

`-1` は「指定なし＝書込レイヤ」、`0 0 -11` は「書込線色・線種・線幅・レイヤ、かつ建具としての
性質を解除」という意味です。**`-1` と `-11` の違いが折戸の包絡不具合の原因**でした。次の節を参照。

### 円弧の指定

```
円弧中心のブロック番号
 | 円弧始点のブロック番号
 |  |   円弧中心の座標      円弧始点の座標   線色 線種 レイヤ  E  角度  コード
 1  2      -10  70            10  70          1   0   -1     E   90   12
```

- **円弧中心＝データ行の始点、円弧始点＝データ行の終点**。半径は両者の距離
- 角度は円弧始点から終点まで。**左廻りが＋**
- コードの**1の位**が作図内容を決める

| 1の位 | 作図されるもの |
|---:|---|
| 0 | 円弧のみ |
| 1 | 円弧 ＋ 中心から始点までの線 |
| 2 | 円弧 ＋ 中心から終点までの線 |
| 3 | 扇形（円弧＋中心から始点・終点の両方） |
| 5 | 中心から始点までの線のみ（円弧なし） |
| 6 | 中心から終点までの線のみ（円弧なし） |
| 7 | 中心から始点・終点の両方の線のみ（円弧なし） |

10の位に `1` を置くと、建具表の円弧・扇形を表示枠内でシザリングして表示します。

コードの1の位を `8` にすると、直前2個の円弧・扇形の終点どうしを結ぶ線を描きます
（座標は各終点からのずれ、角度は0以外のダミー）。折戸の扉厚はこれを使っています。

### 基準寸法と初期値の行

| 書き方 | 意味 |
|---|---|
| `S 100 50` | 見込寸法の基準値を100mm、枠幅寸法の基準値を50mmに設定 |
| `S 100 100` または `S` | 見込・枠幅とも基準値を100mmに設定 |
| `W 1700` | 内法寸法の初期値を1700mmに設定（`W 0` で無指定） |

基準値を指定しない場合、見込は70mm、枠幅は25mmが基準になります。

### 終端（部材データの区切り）

`990`〜`999` の範囲で書きます。**値が一覧表での表示倍率**になり、`999` が等倍、
`990` が0.1倍で、その間は比例します。幅の広い建具を一覧に収めるために小さくします。

終端の後ろに半角スペースで2つ数値を書くと、**見込寸法と枠幅寸法をその値に固定**できます。
`999 100 25` なら見込100mm・枠幅25mm固定です。

### 見込の基準

通常の建具は **Y=0 が見込の基準面**で、見込 0〜70、建具線が Y=35、
端部線は −10〜80（壁の外へ上下10ずつはみ出す）。
はみ出した分は包絡処理で壁厚ぴったりに切り揃えられます。

元データの折戸だけは **Y=0 が折戸の軸そのもの**（±50）という別の基準で描かれていたため、
壁の中心からずれていました。全体を Y+35 して他の建具と揃えてあります。

## 包絡処理の不具合について

### 症状

折戸だけ、**建具用包絡（Shift を押しながらの終点指示＝中間線消去）**をすると端部が崩れました。
普通の建具（ドアー・引違いなど）は正常でした。

### 原因

建具用包絡は**建具属性の付いた線を処理対象**にします。
折戸の羽根はレイヤ欄が `-1`（建具属性あり）だったため包絡の対象になり、
羽根が端部線から**斜めに枝分かれ**することで余計な交点ができて、端部の処理が壊れていました。

羽根のレイヤ欄を **`-11`（建具属性なし）** にすると羽根が包絡の対象から外れ、
端部線と壁だけで包絡が成立して正常になります。

### 切り分けの記録

同じ骨格に要素を1つずつ足して、壁に配置 → 建具用包絡 で確認しました。

| 試したこと | 結果 |
|---|---|
| 端部線の線色・線種・レイヤを変える（`0 0 -11` / `0 1 -11` / `0 0 -1` / `0 1 -1`） | 変化なし。属性取得で正常な建具と同一と確認済み |
| 端部線の長さを変える（±50 / ±65 / −10〜80） | 変化なし |
| 終端コードを変える（999 / 995 / 991） | 変化なし |
| 行の並び順を変える | 変化なし |
| 分割数を変える（2 / 3 / 5 / 9）※端部線＋建具線のみの骨格 | **すべて正常**。骨格自体は問題なし |
| 骨格＋中央の縦線 | 正常。中央線はシロ |
| 骨格＋羽根60度 | **崩れる** |
| 骨格＋羽根90度 | 正常。端部線と重なる向きなら問題ない |
| 羽根を内側へ2mm / 10mm ずらす | 崩れる |
| 羽根の起点を端部線の外（Y=81）へ | 崩れる |
| 羽根を80度に | 崩れる |
| 羽根の建具部分を手作業で曲線属性にする | **正常**（曲線属性は包絡の対象外になるため） |
| **羽根のレイヤ欄を `-1` → `-11` に** | **正常** ← 採用 |
| 羽根のレイヤ欄を `0` / `1` / 属性欄なしに | 線色やレイヤが崩れる。`属性欄なし` は壁と同属性になり包絡に飲み込まれて羽根が消える |

曲線属性でも直りますが、建具データの書式に曲線属性を指定する項目は見つかりませんでした。
`-11` なら DAT だけで完結し、配置のたびに手作業をする必要がありません。

## 折戸の組み立て方

羽根は分割点を結ぶ線を始点まわりに回転させて描きます。座標のオフセットは mm 固定で
建具幅に追従しないため、折れ点を直接指定することはできず、この方法しかありません。

羽根の長さ L と足元の間隔 d の関係は **d = 2L cosθ**（θ＝開き角）です。

| 建具 | θ | cosθ | d | 分割数 | 羽根 |
|---|---|---|---|---|---|
| 開き75度（配布版13番） | 75.5225° | 1/4 | L/2 | 9 | 分割点2つ分 = 幅の1/4 |
| 開き60度（配布版から削除） | 60° | 1/2 | L | 9 | 分割点2つ分 = 幅の1/4 |

開き60度はもともと分割5で書かれていましたが、開き75度と同じ形式（分割9・内側の羽根は
90度を超える回転）に揃えてあります。**描かれる線の位置は分割5のときと完全に同じ**で、
書き方だけが変わりました。それでも包絡は直らず、配布版からは外しています（後述）。

## 片引戸の引き込み位置の破線

引き込んだ位置を示す破線は、開口の左隣に**建具幅と同じ長さ**で必要です。
座標のオフセットは mm 固定で建具幅に追従しないため、そのままでは引けません。

そこで **P1→P3（長さ＝建具幅）の線を始点まわりに180度回して左へ向ける**という書き方にしています。

```
1 3 0 100 0 100     6 0 -11              ← 戸（閉じた位置）
1 3 0 100 0 100     2 2 -11  e  180  16  ← 戸（引き込んだ位置・点線）
```

2行は座標が同じで、後者だけ180度回っています。回転は始点まわりなので、
終点が P1 から左へ建具幅ぶん振られます。建具幅を変えても破線の長さが追従します。

戸の2本には**建具属性を付けていません（`-11`）**。壁の外（Y=100）にあるため、
建具属性を付けると包絡で壁厚に切り詰められてしまいます。

## 扉の線と円弧を別の線色にする方法

扉の線と開き軌跡の円弧は1行から両方描かれますが、線色欄は1つしかありません。
**円弧だけを描くコード（1の位が0）と、線だけを描くコード（1の位が6）を使って2行に分けます。**

```
1 3 0  35  0  35    2 0 -11  e  90  10   ← 円弧だけを線色2で
1 3 0  35  0  35    6 0 -11  e  90  16   ← 扉の線だけを線色6で
```

親子ドアーの子扉は、閉じた位置の線（＝その区間の建具線）も要るので
1の位を `1`（円弧＋中心から始点までの線）にしています。

```
2 2 300  50   0  50   2 0 -1   e  -90  11   ← 円弧と閉じた位置の線を線色2で
2 2 300  50   0  50   6 0 -1   e  -90  16   ← 扉の線だけを線色6で
```

重なる線はありません。

## 中心線について

1・11番には建具の中央を示す縦線が入れてあります。

```
2 2 0 -50 0 120     6 1 -11
```

- **長さは見込（0〜70）の上下に50ずつ**で Y −50〜120。壁から50mmずつはみ出します
- **建具属性を付けていません（レイヤ欄 `-11`）**。付けると建具用包絡で壁厚ぴったりに
  切り詰められ、はみ出しが消えてしまいます
- 線色6・実線の固定です

**中心線を置くには分割数を増やす必要があります。** 座標は分割点からのオフセットでしか
指定できず、分割数2では基準点が両端の2つしかないため中央を指せません。分割数3にすると
真ん中の基準点ができるので、そこに縦線を置いています。既存の行は `1 2`→`1 3`、
`2 2`→`3 3` と読み替えただけで、描かれる形は変わりません。

折戸は元から中央に縦線を持っているのでそれを流用しました。
こちらは長さ（Y −15〜85）も建具属性（`-1`）も元のままで、線色だけ6にしています。

### 片引戸（6番）の中心線だけ建具属性を付けている

6番だけは `2 2 0 -50 0 120  6 1 -1` と**建具属性あり**にしてあります。
`-11` にすると、包絡したときに**壁の中を通る部分が中間線として消され**、
中心線が上下2本に分断されてしまうためです。

6番には見込線（Y=0 と Y=70）が建具属性付きで入っていて、端部線と合わせて
閉じた領域ができます。そこを横切る線が中間線消去の対象になるものと思われます。
1・11番には見込線が無いため、`-11` のままでも切られません。

建具属性を付けても、この中心線は壁の外へ出た部分が切り詰められることはありませんでした。

## 親子ドアーの子扉寸法について

子扉の寸法は**座標に直接書かれた固定値**です。12番なら次の4か所の `300` がそれにあたります。

```
2                            親子ドアー（子扉300）
s    100  100
1 1   0   0   0 100   0 0 -11              ← 左端部線
1 2   0  50   0  50   2 0 -1               ← 建具線（P1→P2）
2 2 300   0 300 100   0 0 -11              ← 右端部線（P2 から右へ 300）
1 2   0  50   0  50   2 0 -1  e   90  12   ← 親扉（P1→P2）
2 2 300  50   0  50   2 0 -1  e  -90  13   ← 子扉（P2+300 → P2）
991  100  100
```

この書式で**指示した幅に追従できるのは分割点で表した寸法だけ**で、mm で直接書いた寸法は必ず固定です。
分割数 n は指示幅を (n−1) 等分するため、比率でしか表せません
（折戸が分割9＝8等分でこれを使っています）。

実際の親子ドアは子扉が定尺なので、比率にすると実物と合いません。
そのため**寸法違いを別の建具として登録**する方式にし、子扉400・450 を14・15番に足しました。
別の寸法が要るときは `tools/build.py` の `WIDTHS` に足します。

`s`/`S` の行と終端の `995`・`991` に寸法入力の仕組みがありそうですが、
各コードの意味は確認できていません（下記「確認できていないこと」参照）。

### 親子ドアー（12・14・15番）の見込は100

親子ドアーだけ見込が 0〜100・建具線が Y=50 で、他の12件（0〜70・Y=35）と基準が違います。
端部線のはみ出し（他の建具の上下10mm）もありません。見込100の壁で使う前提のデータです。

## 折戸（開き60度）を外した理由

建具用包絡をかけると、**内側の2本の羽根が下へ延長されて壁の下で交わり**、形が破綻します。
開き75度の方は同じ作りでも正常です。

原因は開き角そのものにあると見ています。内側の羽根を足元から下へ延長したとき、
左右の延長線が交わる深さは次のようになります。

| 建具 | 足元の位置 | 開き角 | 交点までの深さ |
|---|---|---|---|
| 開き60度 | 幅の1/4 | 60° | 幅の **0.43倍** |
| 開き75度 | 幅の1/8 | 75.5° | 幅の **1.45倍** |

建具幅900mmなら、60度は390mm下、75度は1300mm下です。
包絡が線を繋ぐ距離に上限があるとすれば、60度だけが引っかかるのは自然です。
この深さは開き角と羽根の配置で決まるため、**60度の形を保ったまま遠ざけることはできません。**

試したことと結果:

| 試したこと | 結果 |
|---|---|
| 羽根の線種を実線から書込線種に | 崩れる |
| 開き75度と同じ組み立て方に（分割5 → 分割9） | 崩れる。描かれる線は分割5のときと同一なので当然 |
| 羽根の線色を2に戻す・建具線も6にする・羽根に建具属性を付ける | 見た目の指定と両立しないため不採用 |

羽根を包絡の対象から完全に外せれば直りますが、それには曲線属性が要り、
DAT で曲線属性を指定する方法は見つかっていません。
必要になったら `JW_OPT1B_扉厚折戸入り.DAT` から戻せます。

## 扉厚を描く詳細版の折戸を外した理由

折戸には無い `e 10 18` という行が元の15・16番には各4行あり、
これは**回転の中心が分割点そのもの**だと考えられます。

元データは折戸の軸が Y=0、つまり分割点と一致していたので成立していましたが、
軸を壁の中心に合わせるため全体を Y+35 したことで、回転の起点（Y=35）と
回転の中心（Y=0）が35mmずれました。この2件は扉厚を表すために回転を数珠つなぎに
しているため、そのずれが増幅して形が破綻します。

軸を戻せば形は直りますが、今度は壁の中心からずれて包絡も効かなくなり元に戻ってしまいます。
**「軸を壁中心に合わせる」と「扉厚を表現する」が両立しない構造**です。

1/100 の図面に扉厚は不要なため、配布版からは外しました。
必要になったら `JW_OPT1B_扉厚折戸入り.DAT` から戻せます。

## 書式の出典について

当初は解説サイトがこの作業環境のプロキシに遮断されていて読めず、書式は元データの解析と
Jw_cad 上での実挙動からの推測で埋めていました。

その後 `JW_OPT1_元データ.DAT` の末尾に**Jw_cad 公式の「パラメトリック建具データ説明」が
そのまま収録されている**ことがわかり、上記「データの書式」はその内容に置き換えてあります。
推測で書いていた `S` 行・終端の数値・レイヤ欄の桁数・円弧のコードは、すべて説明どおりでした。

説明文はデータの最終建具の終端より後ろにあるため、Jw_cad は読み飛ばします。
資料として残す価値があるのでファイルからは削っていません。
