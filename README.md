# Jw_cad 外部変形「文字位置揃え」

範囲選択した文字の位置を、**横方向(X)** と **縦方向(Y)** をそれぞれ独立に指定して揃える Jw_cad の外部変形です。
Jw_cad Version 8.20 で動作確認済みです。

Jw_cad の標準機能（範囲選択 → 文字位置・集計）では横方向の整理が中心で、縦方向を含めた一括の揃えは手数がかかります。この外部変形は横・縦を別々に指定して一度に揃えます。

## 使い方（かんたん）

1. `dist/` の中身をフォルダごと Jw_cad の外部変形フォルダ（例 `C:\jww\外変\`）にコピー
2. Jw_cad で **[その他] → [外部変形]** → `文字位置揃え.bat` を選ぶ
3. 揃えたい文字を範囲選択 → 選択確定
4. 横方向の揃え方を番号で入力 → 縦方向の揃え方を番号で入力

| 番号 | 横方向(X) | 縦方向(Y) |
|:--:|---|---|
| 0 | 揃えない | 揃えない |
| 1 | 左揃え | 下揃え |
| 2 | 中央揃え | 中央揃え |
| 3 | 右揃え | 上揃え |
| 4 | X座標を数値指定（文字の左端） | Y座標を数値指定（文字の下端） |
| 5 | 等間隔（左端どうしを等間隔に） | 等間隔（下端どうしを等間隔に） |
| 6 | 等間隔（文字のすき間を等間隔に） | 等間隔（文字のすき間を等間隔に） |

毎回同じ揃え方をする場合は、問い合わせなしで実行される固定設定のバッチ（`文字位置揃え_左揃え.bat` など8種）を使います。

詳しい説明は [`dist/使い方.txt`](dist/) を参照してください。

## 基準にする文字を指示して揃える

「一番左」ではなく「**この文字に合わせたい**」というときは `文字位置揃え_基準文字指示.bat` を使います。範囲選択のあとに基準にしたい文字をクリックすると、指示した点に一番近い文字が基準になり、左揃え・中央揃え・右揃え（下・中央・上）はその文字に合わせて動きます。基準にした文字自身は動きません。

これは `REM #1` で点を指示させ、その座標が `hp1 x y` として座標ファイルに渡ってくるのを利用しています。

## 等間隔配置

番号 5 / 6 を選ぶと、選択した文字を等間隔に割り付けます（`文字位置揃え_横に等間隔.bat` / `文字位置揃え_縦に等間隔.bat` でも実行可）。

- **5** … 文字の左端（下端）どうしが等間隔になるように動かす
- **6** … 文字と文字のすき間が等間隔になるように動かす。文字数がバラバラでも見た目の間隔がそろう

両端の文字は動かさず、間の文字を割り付けます。文字が3個以上ないと何も起こりません。

## 揃えの基準

- **左揃え / 右揃え** … 座標ファイルが持つ文字列の実長を使うため、文字数や文字種が違っても左端・右端がそろう
- **上揃え** … 文字種の文字高さ（`hch` / `cn0`）を見て上端をそろえる
- **下揃え** … 文字の基準点（左下）をそろえる
- **中央揃え** … 選択した文字全体の外形の中心に合わせる

## 仕組み

```
Jw_cad ──① 選択した文字を jwc_temp.txt に出力
        └─② 文字位置揃え.bat を起動
              └─③ jww_text_align.vbs が座標を書き換える
        ──④ jwc_temp.txt を読み戻して作図
```

バッチファイルの制御行:

| 制御行 | 意味 |
|---|---|
| `REM #jww` | jww 形式の座標ファイルを受け取る（この行が無いと外部変形の一覧に出ない） |
| `REM #h3` | 範囲内の**文字データだけ**を `jwc_temp.txt` に書き出す |
| `REM #hc …` | 範囲選択時に表示するメッセージ |
| `REM #1 …` | 点を指示させる。指示点は `hp1 x y` として渡される（基準文字指示用のバッチのみ） |
| `REM #e` | 制御文字列の終わり |

出力する `jwc_temp.txt`:

- 先頭に `hd` を書いて、選択された元の文字を削除する
- 続けて、座標を書き換えた `ch` 行と、元の属性行（`ly` / `lc` / `cn` など）をそのまま出力する
- 実行済みの印として、読み込んだ `hq` などの図面情報行は出力しない

### 文字データの解釈について

文字データ `ch 始点X 始点Y ○ ○ "文字列` の第3・第4フィールドは、資料によって「文字列の長さ成分」と「終点座標」の2通りの説明があります。本スクリプトは読み込んだデータから**実行時に自動判定**し、どちらでも正しく動くようにしています（水平な文字なら、前者は第4=0、後者は第4=始点Y になることを利用）。

誤判定した場合は、実行後に作られる `jww_text_align.ini` の `CHFORMAT` を `auto` から `rel`（長さ成分）または `abs`（終点座標）に書き換えて固定できます。

## 動作確認

`dist/テスト/テスト実行.bat`（通常）と `dist/テスト/テスト実行_基準文字.bat`（基準文字を指示した場合）を実行すると、サンプルの座標ファイルを処理して結果をメモ帳で表示します。Jw_cad の図面を触らずに動作を確認できます。

## 注意事項

- 元の文字は `hd` で削除され、同じ内容の文字が新しい位置に書き直されます。結果がおかしいときは Jw_cad の **[戻る]** で元に戻せます。
- 寸法図形の寸法文字や、ブロック図形の中の文字は選択しないでください。
- 傾いた文字は、上下の高さを考慮せず基準点（左下）を基準に揃えます。
- 動作には `cscript.exe`（Windows Script Host）が必要です。

# Jw_cad 外部変形「描画順（重なり順）」

Jw_cad の重なり順は「後から作図したものが上」です。この外部変形は、範囲選択したデータを**線色番号などの番号順に並べ替えて書き戻す**ことで、重なり順を番号で指定します。

## なぜ並べ替えられるのか

Jw_cad は `jwc_temp.txt` に書かれた順にデータを作図するので、**ファイルの後ろにあるものほど上**になります。外部変形は「選択データを `hd` で消して、返した順に描き直す」ことができるため、返す順番＝新しい重なり順になります。

```
Jw_cad ──① 選択したデータを jwc_temp.txt に出力
        └─② 描画順.bat を起動
              └─③ jww_draw_order.vbs が並べ替える
        ──④ jwc_temp.txt を読み戻して作図（＝書いた順に重なる）
```

そのため、**並べ替えの対象は範囲選択したデータだけ**で、選択しなかったデータより必ず上に来ます。重なりを整理するときは、重なっているものをまとめて選択してください。

## かんたん版（実務用・設定なし）

線色 `1,2,3,4,6,5,7,8` の順に直せれば十分、という場合は **`jww_draw_order_simple.zip`** を使ってください。**書き替える設定はひとつもありません。**確認ダイアログも出ません。

```
線の重なり順\
  ├ 線の重なり順を直す.bat
  ├ jww_draw_order.vbs
  ├ ボタンを出す.bat        ← 任意
  ├ ボタンを出す.ahk        ← 任意
  └ お読みください.txt
```

フォルダごと**書き込みのできる場所**（`ドキュメント\線の重なり順\` など）にコピーするだけで準備完了です。中のファイルは同じフォルダに置いたままにしてください。

> **コピー時に「アクセス許可が必要です」と出る場所には置かないでください。** `C:\Program Files\` 配下のほか、`C:\jww\` のような **`C:\` 直下に作られたフォルダ**も該当します（`C:\` 直下は既定で管理者しか書き込めず、UAC の昇格が必要です）。Jw_cad 本体がそこにあっても関係ありません。管理者権限で押し込んでも、外部変形は実行時に `jwc_temp.txt` を書き出すため、通常権限の Jw_cad から書けずに失敗します。

**そのまま使う（追加ソフト不要）**: **[その他] → [外部変形]**（ツールバーの `[外変]` ボタンでも可）→ `線の重なり順を直す.bat` → `[全選択]` → `[選択確定]`。

**ボタンで使う（ボタン1回で完了）**: `ボタンを出す.bat` をダブルクリックすると画面右上に `[線の重なり順]` ボタンが出ます。**ボタンを1回押すだけ**で、外部変形の起動 → `[全選択]` → `[選択確定]` まで自動で走ります（[AutoHotkey v2](https://www.autohotkey.com/) が必要）。設定項目はありません。バッチの場所は `A_ScriptDir` から自動で解決します。

各段階は名前の決め打ちを避けています。外部変形は全メニューを走査して「外部変形」を含む項目のコマンド番号を `WM_COMMAND` で直接送り（Jw_cad 8.20 では `32913`）、ファイル選択は Jw_cad 独自ウィンドウなので `SysListView32` の行を探して選び、`[全選択]` / `[選択確定]` は `jw_win.exe` の全ウィンドウのコントロールを走査して該当テキストを持つものを押します。うまく動かないときは `[?]` ボタンでウィンドウ・メニュー・コントロール・ファイル一覧を `Jw_cad調査.txt` に書き出せます。

**ホットキーは使っていません。** キーを常時監視するスクリプトはウイルス対策ソフトに「キーロガー」と誤検知されやすいため、操作は GUI のボタンのみにしています。それでも隔離される場合は、フォルダを検査の対象外に指定してください。

`.ahk` を直接ダブルクリックすると、`.ahk` が別のアプリ（Jw_cad など）に関連付けられている環境では**そちらが起動して「読めないファイルです」になります**。`ボタンを出す.bat` は AutoHotkey の実行ファイルを標準的なインストール先から自分で探して起動するので、関連付けの影響を受けません。見つからない場合はその旨を表示して終了します。

**ブロック図形の除外は必須です**: ブロック図形を範囲に入れると図面から**消えます**（外部変形から書き戻す手段がないため）。ブロック図形を置いたレイヤを **[表示のみ]** にしておけば `[全選択]` の対象から外れます。範囲に入っていた場合は、かんたん版でも必ず確認ダイアログを出すので、[いいえ] を選べば図面は変わりません。曲線属性の図形と寸法図形はまとまりを保ったまま並べ替えられるので、範囲に入れて構いません。

以下は全機能版（`jww_draw_order.zip`）の説明です。

## 使い方（かんたん）

1. `dist/描画順/` をフォルダごと Jw_cad の外部変形フォルダ（例 `C:\jww\外変\`）にコピー
2. Jw_cad で **[その他] → [外部変形]** → `描画順.bat` を選ぶ
3. 重なり順を変えたいデータを範囲選択 → 選択確定
   （文字も対象にするときは、範囲の終点を**右クリック**）
4. 並べ方を番号で入力 → 番号の種類を入力

| 番号 | 並べ方 |
|:--:|---|
| 0 | 最前面へ（選択したものを、そのまま一番上に） |
| 1 | 番号順（番号の大きいものが上） |
| 2 | 番号順（番号の小さいものが上） |
| 3 | 並び順を自分で指定（`3,1,2` … 先頭が下、末尾が上） |
| 4 | 指定した番号だけを最前面へ（`2,5` など） |
| 5 | 指定した番号だけを最背面へ |

順番を決める「番号」は 4 種類から選べます。

| 番号 | 種類 |
|:--:|---|
| 1 | 線色番号（線色1〜線色9） |
| 2 | 線種番号（実線=1 …） |
| 3 | レイヤ番号（0〜15。A〜F は 10〜15） |
| 4 | レイヤグループ番号（0〜15） |

同じ番号どうしの重なり順は元のままです（安定ソート）。

毎回同じ操作をする場合は、問い合わせなしで実行される固定設定のバッチを使います。

| バッチ | 動作 |
|---|---|
| `描画順_最前面へ.bat` | 選んだものをそのまま一番上へ |
| `描画順_線色番号順.bat` | 線色1 が下 … 線色9 が上 |
| `描画順_線色番号順_逆.bat` | 線色9 が下 … 線色1 が上 |
| `描画順_線色順_12346578.bat` | 下から `1,2,3,4,6,5,7,8` の順に重ねる |
| `描画順_レイヤ番号順.bat` | レイヤ0 が下 … レイヤF が上 |
| `描画順_線色指定で最前面.bat` | 入力した線色だけを一番上へ |
| `描画順_線色指定で最背面.bat` | 入力した線色だけを一番下へ |

## 環境設定ファイル（jw_win.jwf）では指定できません

「`jw_win.jwf` を書き替えれば線色順に描画できるのでは」と考えがちですが、**jw_win.jwf に描画順を線色で指定する項目はありません。**

`jw_win.jwf` に入っているのは、基本設定ダイアログで設定できる項目そのものです。線色に関係するキーは次の 2 つだけで、どちらも「色」と「線幅」を決めるだけです。

| キー | 内容 | 項目 |
|---|---|---|
| `LCOLLOR_1` 〜 `LCOLLOR_8` | 画面上の線色1〜8 | R, G, B, 画面線幅 |
| `PCOLLOR_1` 〜 `PCOLLOR_8` | 印刷時の線色1〜8 | R, G, B, 印刷線幅, 端点処理 |

ほかのキーも、線種パターン（`LTYPE_*`）、レイヤ名と個別指定（`LAYNAM_*` / `LAYCOL_*` / `LAYWID_*` / `LAYTYP_*`）、文字設定（`MWIDE` / `MHIGH` / `MPEN` など）、寸法設定（`S_STR*` / `S_SET*`）、ハッチ（`HATCH_*`）、キー割付とクロックメニュー（`KEY_*` / `LD_AM` など）で、**描画順を並べるためのテーブルは存在しません。**

Jw_cad にある唯一の描画順の設定は、基本設定 [一般(1)] の **「画像・ソリッドを最初に描画」** です。これは画像とソリッドをまとめて他より先に（＝背面に）描くもので、線色ごとの順番は指定できません。この項目は `jw_win.jwf` では `S_COMM_` 行の数値に**ビットとして**埋め込まれていて、キー名が付いていません。書き替えたい場合は [jwf設定比較](#jw_cad-環境設定ファイル比較jwf設定比較) でビット位置を特定できます。

つまり Jw_cad の描画順は**作図順（データの並び順）だけ**で決まります。線色順にしたければ、その順に並べ直して描き直すしかありません。それを自動でやるのがこの外部変形です。

## 起動時の自動実行はできません

Jw_cad の起動時に自動で効かせることはできません。理由は3つあります。

1. Jw_cad には**起動時にマクロを実行する仕組みがありません**（プラグイン機構も無し）
2. 外部変形は**範囲選択が必須**で、範囲が決まらないと `jwc_temp.txt` が作られず処理が始まりません
3. 最も本質的な点として、**描画順は「データの並び順」そのもの**であって表示設定ではありません。起動時に1回並べ替えても、そのあと描いた線はまた一番上に乗ります。「一度設定すればずっと効く」性質のものではありません

図面ファイル（`.jww`）は独自のバイナリ形式で、しかも編集中のデータは Jw_cad のメモリ上にあるため、ファイルを監視する常駐スクリプトも実用になりません。

現実的にできるのは**「キー1つで実行する」ところまで**です。作図が一区切りついたところで押す、という使い方になります。

## 常駐ホットキー

`dist/描画順/常駐/描画順ホットキー.ahk`（[AutoHotkey v2](https://www.autohotkey.com/)）を常駐させると、Jw_cad の操作中にキー一発で外部変形を実行できます。

| キー | 動作 |
|---|---|
| `Ctrl + Alt + ↑` | 選んだものを最前面へ |
| `Ctrl + Alt + ↓` | 指定した線色を最背面へ |
| `Ctrl + Alt + L` | 線色順 `1,2,3,4,6,5,7,8`（範囲は手で選ぶ） |
| `Ctrl + Alt + A` | 同上を**図面全体に適用**（全選択 → 選択確定 まで自動） |
| `Ctrl + Alt + O` | 描画順（対話式） |

`Ctrl + Alt + A` はメニュー操作からコントロールバーの [全選択] → [選択確定] まで自動で押すので、キー1回で図面全体が並び替わります。

**使う前に**: [全選択] が拾うのは「編集可能なレイヤー」のデータだけです。**ブロック図形**と、**複数の線色が混ざった曲線属性の図形**を置いたレイヤーは、**[表示のみ] にしておけば全選択の対象から外れます**。これが実質的な保護になります。最初は必ずコピーした図面で試してください。

メニューはアクセラレータキーではなく**項目名**（`MenuSelect`）でたどるので、メニューの並びが変わっても動きます。スクリプト冒頭の `BAT_DIR` を実際の設置場所に書き換えてから使ってください。コントロールバーのボタンが押せない環境では `REAL_CLICK := true` にすると実際にマウスを動かして押します。

AutoHotkey を入れたくなければ、通常どおり [その他] → [外部変形] から選ぶだけでも使えます。

## 並べ替えても属性が壊れない理由

`jwc_temp.txt` の属性行（`lg` / `ly` / `lc` / `lt` / `cn`）は「次に同じ行が現れるまで有効」という**状態**なので、要素だけを並べ替えると属性の対応がずれてしまいます。そこで本スクリプトは、

- 読み込み時に、各要素へ「そのとき有効だった属性行」を持たせる
- 書き出し時に、直前の要素から**変わった属性行だけ**を書き直す
- 種類の分からない行は、直後の要素にくっつけて一緒に動かす（ソリッドの色指定など、要素を修飾する行は必ず要素の前に置かれるため）
- 読み終えた時点の書込属性を末尾に書いて、書込レイヤ・線色が変わらないようにする

という処理をしています。

バッチファイルの制御行は `REM #h1`（範囲内の図形と文字を書き出す）を使っています。

## 動作確認

`dist/描画順/テスト/テスト実行_線色順.bat` と `テスト実行_対話.bat` で、Jw_cad の図面を触らずに動作を確認できます。線色・線種・レイヤの違う線／円／文字／ソリッドが混ざったサンプルを処理し、結果をメモ帳で表示します。

## 注意事項

- 並べ替えの対象は**範囲選択したデータだけ**です。選択しなかったデータはすべて下になります。

### データの種類ごとの結果（Jw_cad 8.20 で実測）

| 種類 | 結果 |
|---|---|
| **ブロック図形** | **消えます。**`BL` 行で渡されますが、外部変形から書き戻す手段がありません。実行前に必ず確認ダイアログを出します |
| 曲線属性（1色だけ） | 保たれます |
| 曲線属性（複数の線色が混在） | 線色ごとに分かれます |
| 寸法図形 | 保たれます |
| 線・円・円弧・楕円・点・文字・ソリッド | 座標も内容も変わりません |
| 線色・線種・レイヤ・レイヤグループ・文字種・フォント・点の種類・ソリッドの色 | 保たれます |

**ブロック図形が消える理由**: Jw_cad はブロック図形を次の形で渡してきます。中身は展開されず、配置だけが 1 行で表されます。

```
BL 66975.8239205113 37216.7542667412 "1
#
```

`BL` は Jw_cad から外部変形への一方通行で、**書き戻しても復元されません**（同じ形で返して実機で確認済み。ブロック図形は消えました）。`hd` で消したものを戻せないため、範囲に入れると図面から消えます。

そのため `ConfirmBlocks()` が `BL` の数を数え、**1 個でもあれば必ず確認ダイアログを出します**。[いいえ] を選ぶと `jwc_temp.txt` を書き換えずに終了するので、図面は変わりません。`/nowarn` でも抑制しません（消えるのは警告ではなく実害のため）。ブロック図形を置いたレイヤを **[表示のみ]** にすれば、`[全選択]` の対象から外れてダイアログも出なくなります。

### `pl` / `msg` / `#` — まとまりの区切り

実際の `jwc_temp.txt` を採取して判明した仕様です。

| 行 | 意味 |
|---|---|
| `pl` | 曲線属性（ポリライン）の始まり |
| `msg` | 寸法図形の始まり |
| `BL` | ブロック図形の配置（`BL x y "ブロック名`） |
| `#` | まとまりの終わり |

```
msg
lc2
 -28692.98 13128.83 -28692.98 -4871.89     ← 寸法線
cn4
cs -28712.98 3678.47 0 900 "18,001         ← 寸法値
#
```

`jww_draw_order.vbs` は当初 `#` をコメント行として捨てており、まとまりの終わりが消えていました。さらに `pl` / `msg` を「種類の分からない行」として扱っていたため、要素ごとに並べ替えられてまとまりが分断されていました。**混色の曲線属性が線色ごとに分かれる原因はここでした。**

現在は `pl` / `msg` / `BL` のまとまりを **1 つのレコード**として扱い、かたまりごと動かします。まとまりの終わりの判定は 2 通りです。

| 先頭 | まとまりの終わり |
|---|---|
| `pl` / `BL` | 続く**作図要素の行**が途切れたところ。直後に `#` があれば取り込む |
| `msg` | `#` の行（中に `lc` / `cn` の属性行が入るため） |

`pl` の終わりを「次の `pl` まで」と広く取ると、図面のほとんどが数個の巨大なかたまりになり並べ替えが効かなくなります。実データ 6 組すべてで、**`#` が付くのは次が属性行でないときだけ**でした。

### 書き戻しは読み込みと対称ではありません

`#` の扱いは方向で違います。

| まとまり | 書き戻し |
|---|---|
| `msg`（寸法図形） | `#` で閉じる。寸法図形として復元される |
| `pl`（曲線属性） | **`#` を書いてはいけない。**書くと曲線属性が線 1 本ずつにばらける（実機で確認） |
| `BL`（ブロック図形） | `#` を書いても書かなくても復元されない |

`pl` は `#` の代わりに、まとまりの直後へ**線色の行を必ず置いて**閉じます（`IsPolyBody()` で判定し、`lastLc` を捨てて次のレコードに線色を書き直させる）。属性行がまとまりを閉じるという Jw_cad 自身の出力規則を、そのまま書き戻しに使っています。

同じ理由で、**複数の線色が混ざった曲線属性は線色ごとに分かれます**。まとまりの途中に入る線色の行が、そこでまとまりを閉じてしまうためです。書き戻しの決まりの問題なので、外部変形の側では避けられません。

あわせて、文字フォント行（`cn"$<…>`）を文字種行（`cn0 …`）と別に保持し、点の種類行（`pn6`）を点の属性として保持するようにしました。

### 危ないデータの検出

スクリプト側で「これは残す」という選び方は**できません**。`jwc_temp.txt` に書き戻すかどうかは `hd` による全消しか、何もしないかの二択で、要素ごとに残す手段が無いためです。

そのため、**実行前に検出して中止できる**ようにしています。寸法コマンドで作られた文字（`cs` 行）や、種類の分からないデータ行が見つかったときだけ確認ダイアログを出し、[いいえ] なら `jwc_temp.txt` を書き換えずに終了します（Jw_cad 側は「未実行」となり図面は変わりません）。`/nowarn` で抑制できます。

### ビルド時の .vbs 検査

`tools/check_vbs.py` が `src/` 配下の `.vbs` を静的に検査し、`tools/build.py` の先頭で実行されます。検査は次の 3 点を見ます。

1. `Sub` / `Function` / `If` / `For` / `Do` / `Select` の対応
2. **呼んでいるのに定義が無い手続き**（`Option Explicit` では実行時エラー 500「この変数は宣言されていません」になる）
3. 同じ名前の手続きの二重定義

2 は実際に起きた事故です。まとまり読み取りの関数を差し替えたときに範囲指定を誤り、後続の関数 5 個（`IsAttrLine` / `IsElementLine` / `IsTextBody` / `IsPointBody` / `PushRec`）をまとめて削除してしまい、Jw_cad 側が「未実行」になりました。検査に落ちた場合、`build.py` は `dist/` を作らずに終了します。

**恒久的な除外はレイヤで行います。** ブロック図形と、混色の曲線属性の図形を置いたレイヤを **[表示のみ]** にしておけば、範囲選択の対象そのものから外れるので、以後は自動的によけられます。

### 調査用の `/dump`

バッチファイルの `cscript` の行に `/dump` を足すと、Jw_cad から受け取った内容と書き戻した内容が `.vbs` と同じフォルダに残ります。

| ファイル名 | 内容 |
|---|---|
| `jwc_temp_元.txt` | Jw_cad が外部変形に渡してきた内容 |
| `jwc_temp_結果.txt` | 外部変形が Jw_cad に返した内容 |

かんたん版には `調査_データを書き出す.bat` として同梱してあります。
- 結果がおかしいときは Jw_cad の **[戻る]** で元に戻せます。
- 動作には `cscript.exe`（Windows Script Host）が必要です。
- 前回指定した内容は `jww_draw_order.ini` に記憶されます。

# Jw_cad 環境設定ファイル比較「jwf設定比較」

2 つの `jw_win.jwf` を比べて、**どのキーの何番目の数値が変わったか**、16進の数値なら**どのビットが ON / OFF になったか**を報告します。

基本設定のチェック項目は `jw_win.jwf` の中では `S_COMM_` 行の数値にビットとして詰め込まれていて、キー名が付いていません。そのため「このチェックはどの数字のどのビットか」は資料からは分からず、**実際に切り替えて前後を比べるのが唯一確実な方法**です。このツールはその比較を自動でやります。

## 使い方

1. Jw_cad で、調べたいチェックを**外した**状態にする
2. **[設定] → [環境設定ファイル] → [書出し]** で `変更前.jwf` として保存
3. **[設定] → [基本設定]** で、調べたいチェックを**1つだけ**入れる
4. もう一度 **[書出し]** で `変更後.jwf` として保存
5. その 2 つを `jwf設定比較.bat` にドラッグ＆ドロップ

出力例:

```
[S_COMM_0]
    1 番目 : BB  →  FB
        16進として  BB = 1011 1011
                    FB = 1111 1011
        ON になったビット  : 0x40（10進 64）
```

この場合、`S_COMM_0` の 1 番目を `BB` から `FB` にすればそのチェックが入った状態になります。特定さえできれば、以後は複数の `.jwf` を手で書き替えて配布できます。

## 注意事項

- チェックを1つだけ変えたのに複数のキーが変わったときは、書き出すたびに変わる項目（表示範囲など）が混ざっています。同じ操作をもう一度行い、毎回変わるキーを除いて判断してください。
- 「16進として」の表示は、値が `0-9` `A-F` だけでできている場合に出ます。もともと10進の項目にも表示されるので、その場合はビットの説明を無視してください。
- `.jwf` を手で書き替えるときは、区切りに**必ず半角スペース**を使ってください。全角が混ざると Jw_cad が読み込みません。
- 書き替える前に元の `jw_win.jwf` のコピーを取ってください。

# ファイル構成とビルド

```
src/     編集用の原本（UTF-8 / LF）
dist/    そのまま使える実体（CP932 / CRLF）  ← Jw_cad に入れるのはこちら
tools/   src → dist の変換スクリプト
```

Jw_cad はバッチファイルの `REM` 行と `jwc_temp.txt` を Shift_JIS で読み書きするため、配布する実体は CP932 + CRLF である必要があります。リポジトリ上で読みやすいよう原本は UTF-8 で持ち、次のコマンドで変換します。配布用の ZIP も同時に作られます。

```sh
python3 tools/build.py
```

AutoHotkey スクリプト（`.ahk`）だけは例外で、UTF-8（BOM 付き）+ CRLF で出力します。BOM が無いと AutoHotkey がシステムの ANSI として読んでしまうためです。

`REM` 行の説明文に `#` を書くと Jw_cad が制御文字列として解釈してしまうため、バッチファイルのコメントには `#` を使っていません。
